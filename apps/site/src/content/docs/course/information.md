## 这门课做什么

本课程用 8 周时间，带你一个模块一个模块地搭建一个**自动化软件工程系统**。系统的输入是一份按课程格式写的需求文档，输出是一个可以 clone 下来、照 README 安装使用的 Python 命令行程序仓库。

系统由 4 个子智能体组成，每个 Lab 构建其中一个：

| 模块           | 职责                                           | 在哪个 Lab 构建 |
| -------------- | ---------------------------------------------- | --------------- |
| 需求分析与规约 | 把需求文档整理成结构化规约、接口目录和功能切片 | Lab 1           |
| 架构与接口设计 | 给出模块划分、接口签名、需求追溯与实现计划     | Lab 2           |
| 实现与集成     | 按设计生成可以安装、运行的目标仓库             | Lab 3           |
| 测试与修复迭代 | 生成测试、运行、定位失败，再驱动其他模块修复   | Lab 4           |

几点约定：

- **编排**：整个系统是一个 [iCode](https://github.com/openJiuwen-ai/iCode) 工作流，只用 iCode 自身的能力（智能体配置、子智能体、Skills、工作流），不引入其他编排框架。
- **系统内部的模型**：所有子智能体只用 Qwen3.8-27B，使用课程发给小组的 API Key。
- **课程的重点是方法**：我们希望你学会如何把需求分析、设计、实现、测试这些软件工程方法变成智能体能执行的流程。课程不要求你的系统超过某个基线，也不会靠加大任务规模来制造难度。每个 Lab 留有一组设计选择，由你们自己决定并说明理由。
- **评测是自动化的**：每个 Lab 都配有评测工具 `ldsdt`，需求、验收场景和评分依据全部公开，你在本地看到的评测分就是成绩中的评测分（Lab 4 的两项除外，见[评测与提交](../grading/)）。

## 分组与角色

- 全班 52 人，分为 17 组：16 个 3 人组，1 个 4 人组。请在 **11 月 12 日 23:59 前**自由组队，并在钉钉中填写分组表格；届时仍未组队的同学，由助教随机分组。
- **组内角色确定后，整个学期内固定，不可更改。**
- 每组有三种角色：

| 角色  | 做什么                                                                       | 自己的仓库      |
| ----- | ---------------------------------------------------------------------------- | --------------- |
| **A** | 用 AiWork（图形界面）辅助开发一套系统                                        | `<组号>-aiwork` |
| **B** | 用 iCode（终端界面）辅助开发一套系统                                         | `<组号>-icode`  |
| **C** | 不写系统代码；观察并记录 A、B 的开发过程，收集数据，做对比分析，主笔技术报告 | —               |

- 4 人组的第 4 人是第二位 C，两位 C 分别主要观察 A 和 B。
- **A、B 共同商定设计选择**，写进各自仓库的 `design-choices.yaml`，两份内容必须一致。
- **A、B 之间禁止共享代码、提示词和智能体配置文件**，只能口头或文字讨论设计思路。课程组会对两个仓库做相似度检查。
- C 的具体工作见 [C 角色指南](../role-c/)。

## AI 工具使用规则

本课程有两类模型：一类帮**你**写代码（辅助开发），一类在**你的系统**内部运行。两者不能混用。

| 谁           | 允许使用                                                        | 不允许                                             |
| ------------ | --------------------------------------------------------------- | -------------------------------------------------- |
| A            | AiWork 的「编码」页，模型只选 DeepSeek-Flash（AiWork 账号自带） | 其他 AI 编程工具、网页版大模型、IDE 自带的 AI 补全 |
| B            | iCode，辅助开发的模型只用 DS-4.1-flash（课程发放的个人 Key）    | 同上                                               |
| C            | 可以用课程提供的 DS-4.1-flash 辅助整理记录、撰写报告            | 替 A、B 写代码                                     |
| 你的系统内部 | 所有子智能体只用 Qwen3.8-27B（小组 Key，A、B 共用）             | 换用其他模型或其他 Key                             |

- 可以查阅普通网页、官方文档和搜索引擎。
- **如实报告不扣分**：如果你在周记录里如实说明自己违反了上面的规则，不会因此扣分；只有被发现而没有报告的违规才扣分。
- **API Key 只能放在环境变量或本机配置里，不得提交到仓库。** 提交工具会检查。Key 泄露后请立即联系助教更换。

## 提交与迟交

每个 Lab 的提交流程相同：

1. **本地自查**：`uv run ldsdt grade lab<N>` 运行你的系统并打分；
2. **提交**：门槛通过后运行 `uv run ldsdt submit lab<N>`，它会检查有没有误提交的 Key，然后提交运行产物、打标签 `lab<N>-submit` 并推送。截止前可以重复提交，以最后一次为准；
3. **上传会话记录**：运行 `uv run ldsdt collect --week N`，把生成的压缩包上传到学在浙大对应的「会话记录 N」作业，截止时间与仓库提交相同（见[评测与提交](../grading/#会话记录)）；
4. **官方复评**：截止后助教拉取你的标签，用课程组的评测工具副本重新评分。你修改本地评测代码不会影响成绩。

**迟交**：每迟交 24 小时，该 Lab 的评测分乘以 0.9，最多迟交 3 天。如果是模型服务故障或 Key 问题导致延误，凭评测记录里的报错可以申请免责。

## 学术诚信

以下行为一经查实，该 Lab 的评测分记为 0：

- 篡改评测结果或评测工具；
- 手工修改系统生成的产物（规约、设计、目标仓库、测试），当作系统的输出提交；
- A、B 之间共享代码、提示词或智能体配置。

课程组会在每个 Lab 随机抽 3 组复跑系统，核对提交的产物。
