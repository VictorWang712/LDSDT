C 不写系统代码。你的工作是记录 A、B 开发系统的过程，收集数据，比较两种 AI 编程工具的使用方式，并主笔技术报告中的对比分析。

工具会自动留下大量日志：对话内容、命令、文件改动、评测结果。**C 只记录日志里采不到的东西**：开发者的意图和判断、遇到的困难和情绪、问题最后是怎样解决的，以及 A、B 之间的交流。

## 你的任务

| 任务                           | 频率                                                                                   | 记在哪里                        |
| ------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------- |
| 观察工作片段                   | 课堂内全程，每 30 分钟在 A、B 之间轮换；课外每周至少各观察 A、B 一次（现场或屏幕共享） | `research/observation_log.csv`  |
| 写关键事件报告                 | 发生以下情况时：卡住 15 分钟以上、回滚重做、放弃 AI 改为手写                           | `research/incidents/INC-xxx.md` |
| 记录 A、B 的交流               | A、B 之间每次交流                                                                      | `research/sync_log.csv`         |
| 记录设计决策                   | 每个 Lab 的设计选择做出决定时                                                          | `research/decision_log.csv`     |
| 提醒 A、B 运行 `ldsdt collect` | 每周五课后                                                                             | —                               |
| 写子任务对比小结               | 每个 Lab 截止前                                                                        | `research/reports/subtask-N.md` |

4 人组有两位 C，两人分别主要观察 A 和 B，共同完成其余记录。

### 记录放在哪里

所有记录都放在本组 `<组号>-icode` 仓库的 `research/` 目录下，模版仓库里已经有各文件的表头和模板。请 B 在 GitHub 上把你添加为该仓库的协作者（「Settings」→「Collaborators」），你 clone 下来以后直接编辑、提交、推送。

- CSV 文件用 **UTF-8** 编码。Excel 默认可能另存为其他编码，建议用 VS Code 等文本编辑器，或在 Excel 中选择「CSV UTF-8」格式保存。
- 时间统一写成 `YYYY-MM-DD HH:MM`（本地时间，精确到分钟）。课程组要靠时间把你的观察和工具日志对上，请尽量准确。
- 工作片段编号写成 `<组号>-E<三位序号>`，例如 `G07-E031`；关键事件报告编号写成 `INC-001`、`INC-002`……

## 观察日志 `observation_log.csv`

一个**工作片段**是开发者从形成一个目标开始，到达成或放弃这个目标为止的一段工作，通常 5–40 分钟。每个片段记一行：

```csv
episode_id,who,tool,subtask,start,end,goal,delegation,verification,interventions,outcome,problems,recovery,frustration,quote
G07-E031,B,iCode,3,2026-12-04 14:40,2026-12-04 15:05,"让设计模块的输出通过 manifest 检查",stepwise,"run;grade","reprompt=3;manual_edit=1",success,"P1;P6","手工补了 schema 示例再让 AI 改",3,"它每次都忘了 trace 字段"
```

| 字段            | 填写                                                                                                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `episode_id`    | 片段编号，如 `G07-E031`                                                                                                                                                                             |
| `who`           | `A` 或 `B`                                                                                                                                                                                          |
| `tool`          | `AiWork` 或 `iCode`                                                                                                                                                                                 |
| `subtask`       | Lab 编号，0–4；期末写 `final`                                                                                                                                                                       |
| `start`、`end`  | 开始和结束时间                                                                                                                                                                                      |
| `goal`          | 开发者这一段想做成什么，用一句话写                                                                                                                                                                  |
| `delegation`    | 交给 AI 的方式，选一个：`whole`（一次性交给 AI 一个大任务）、`plan_first`（先让 AI 做计划）、`stepwise`（小步推进）、`explain_only`（只问不改）、`manual`（以手写为主）                             |
| `verification`  | 怎样检查 AI 的结果，可多选，用分号分隔：`read_diff`（看改动）、`run`（运行）、`grade`（跑评测）、`manual_test`（手工测试）、`ask_ai`（问 AI 对不对）、`none`                                        |
| `interventions` | 开发者干预 AI 的次数，格式为 `类型=次数`，用分号分隔。类型：`interrupt`（中断）、`reject`（拒绝修改）、`rollback`（回滚）、`manual_edit`（手改）、`reprompt`（重新提问）、`new_session`（开新会话） |
| `outcome`       | `success`、`partial`、`fail` 或 `abandon`                                                                                                                                                           |
| `problems`      | 遇到的问题，用下面的问题编码，多个用分号分隔                                                                                                                                                        |
| `recovery`      | 问题最后是怎样解决的，一句话                                                                                                                                                                        |
| `frustration`   | 你观察到的挫败程度，1（很顺利）到 5（非常挫败）                                                                                                                                                     |
| `quote`         | 开发者说过的有代表性的一句话（可选）                                                                                                                                                                |

含有逗号的字段要用英文双引号括起来。

| ---- | ---------------------------------------- | ---- | -------------------------------------------- |

## 关键事件报告

发生以下情况之一时，写一份 200–400 字的报告：

- 卡住 15 分钟以上；
- 回滚重做；
- 放弃 AI，改为手写。

复制 `research/incidents/INC-000-template.md`，改名为下一个编号（如 `INC-004.md`）后填写：发生了什么、当事人当时的想法、尝试过哪些办法、最后怎样解决。「当事人当时的想法」请在这段工作结束后**花 1 分钟问他本人**，不要自己推测。

只写事实，不写评价。

## 交流记录 `sync_log.csv`

A、B 之间的每次交流记一行：

```csv
time,direction,content_type,summary,crosses_rule
2026-11-27 15:10,A→B,设计,"讨论规约用 JSON 还是 Markdown，决定用 JSON",no
```

- `direction`：`A→B` 或 `B→A`（双向讨论记发起方）；
- `content_type`：`设计`、`报错解决`、`工具技巧`、`代码或提示词`；
- `crosses_rule`：交流内容是否越过了「A、B 之间只能讨论设计、不能共享代码和提示词」的规则，`yes` 或 `no`。

**请如实记录。** 如实记录的越界行为不扣分；被发现而没有记录的才会扣分。

## 设计决策 `decision_log.csv`

每个 Lab 的每个设计维度做出决定时记一行：

```csv
time,subtask,dimension,choice,alternatives,proposed_by,from_ai
2026-11-27 15:30,1,D1.1,JSON 结构化模式,"Markdown;Given-When-Then",A,"yes:AiWork"
```

- `dimension`：维度编号，与 `design-choices.yaml` 一致；
- `alternatives`：讨论过、但没有选的方案，用分号分隔；
- `proposed_by`：最终方案最先由谁提出，`A`、`B` 或 `C`；
- `from_ai`：这个方案是否来自 AI 的建议，`no`，或者 `yes:AiWork`、`yes:iCode`。

## 子任务对比小结

每个 Lab 截止前，复制 `research/reports/subtask-N-template.md`，改名为 `subtask-<Lab 编号>.md` 后填写：

1. A、B 两侧投入的时间和评测得分（得分见各自仓库的 `.ldsdt/grade-history.jsonl`）；
2. 两侧各自最常见的 3 类问题（用问题编码）；
3. 两人与 AI 交互方式最大的不同；
4. A、B 交流的摘要。

**每个论点都要注明依据的片段编号**，例如「B 更倾向于先让 AI 做计划（G07-E012、G07-E019）」。不需要判断哪个工具更好。

## 每周的会话收集

每周五课后，提醒 A、B 在各自的仓库里运行：

```bash
uv run ldsdt collect --week <周次>
```

它会把这一周在该仓库中使用 iCode、AiWork 的会话打包到 `.ldsdt/collect/` 下的一个压缩包里。运行时会列出找到的会话，请和 A、B 一起看一眼列表是否完整：如果 AiWork 的会话一个都没有，通常是因为 A 没有在 AiWork「编码」页的「项目」中打开本仓库。

压缩包**不要提交到 Git 仓库**。上传方式将在第 1 周课上说明。

## 观察纪律

- **不帮忙、不提建议、不评价。** 即使你知道答案，也不要提示。你的介入会改变你要观察的东西。
- **只在工作片段的边界提问**，例如一个目标刚完成或刚放弃的时候，不要在开发者专注时打断。
- 记录观察到的事实。如果是你的推测，请写明「推测」。
- 记录不影响 A、B 的成绩。请如实、完整地记录，包括不顺利的部分。

## 培训与评分

- 第 1 周课上有观察培训：所有 C 观看同一段约 15 分钟的示例录像，独立填写观察日志，然后在课上对照讨论。第 4 周会再做一次。
- C 的个人贡献分（占总成绩 10%）只看记录的**完整性、及时性和规范性**，与 A、B 的得分无关，也与你记录下的问题多少无关。
- 技术报告中的 A、B 对比部分由 C 主笔，写作时直接引用你的记录。
