## 背景知识

### 你要搭建的系统长什么样

整个系统是 iCode 里一个 ID 为 `ldsdt` 的**工作流**，代码放在仓库的 `.chrys/workflows/ldsdt/ldsdt.py`。评测工具这样调用它：

1. 把一份需求文档复制到一个**运行目录**里，例如 `runs/lab0/todo-cli/`；
2. 启动你的工作流，输入是一段 JSON，告诉它需求文档在哪、运行目录在哪、这是第几个 Lab：

   ```json
   { "requirement": "<需求文档的绝对路径>", "run_dir": "<运行目录的绝对路径>", "lab": 0 }
   ```

3. 工作流结束后，检查运行目录里有没有本 Lab 要求的产物，并据此打分。

工作流内部怎么组织（有几个节点、提示词怎么写、要不要校验和重试）完全由你决定。评测工具只看运行目录。

### iCode 工作流的基本概念

- **节点**：工作流由节点组成。**Python 节点**运行一个 Python 函数，适合做解析输入、读写文件、检查结果这类确定性的工作；**智能体节点**把上一个节点输出的文字交给一个智能体（大模型加工具），等它完成任务后，把它的最终回复交给下一个节点。
- **智能体配置**：智能体是什么角色、能用哪些工具，写在仓库 `agents/` 下的 YAML 文件里。运行 `uv run ldsdt sync` 会把它们复制到 iCode 的配置目录，并统一绑定课程的 Qwen 模型配置 `ldsdt-qwen`。
- **连线**：用 `wf.chain(a, b, c)` 把节点依次连起来，数据沿着连线往下传。

模版仓库里的 [`docs/icode-workflow-cheatsheet.md`](https://github.com/VictorWang712/LDSDT-experiment-lab/blob/main/docs/icode-workflow-cheatsheet.md) 是本课程用到的 iCode 工作流写法速查表；[`agents/README.md`](https://github.com/VictorWang712/LDSDT-experiment-lab/blob/main/agents/README.md) 说明了智能体配置的写法。iCode 的完整文档在 [iCode 仓库的 `docs/zh-Hans/`](https://github.com/openJiuwen-ai/iCode/tree/main/docs/zh-Hans) 下。

### 两种模型，不要混用

|              | 用途                                 | 用什么                                                          |
| ------------ | ------------------------------------ | --------------------------------------------------------------- |
| 辅助开发模型 | 帮**你**写工作流、智能体配置和提示词 | A：AiWork 自带的 DeepSeek-Flash；B：iCode 中配置的 DS-4.1-flash |
| 系统内部模型 | 在**你的系统**里运行的智能体         | 只用 Qwen3.8-27B（模型配置 `ldsdt-qwen`，小组 Key）             |

`ldsdt sync` 会自动把 `agents/` 下的智能体绑定到 `ldsdt-qwen`，你不用管。需要注意的是**你自己和辅助工具聊天时用的模型**，见第 6 步。

### 7. 编写热身工作流

这是本 Lab 唯一需要你「开发」的部分。请在辅助开发工具的帮助下完成，借这个机会熟悉怎样让 AI 帮你写 iCode 工作流。

**任务**：修改 `.chrys/workflows/ldsdt/ldsdt.py`，让工作流读入需求文档，用一个 Qwen 智能体列出其中的全部功能需求（编号以 `FR-` 开头的条目），写成运行目录下的 `warmup/fr-list.json`：

```json
{
  "requirement_id": "todo-cli",
  "frs": [
    { "id": "FR-001", "summary": "添加待办事项" },
    { "id": "FR-002", "summary": "列出待办事项" }
  ]
}
```

- `requirement_id` 是需求文档开头 YAML 头部的 `id`；
- `frs` 必须**恰好**包含需求中的全部 FR 编号，不多不少；每条的 `summary` 是一句话概括，不能为空。

**固定要求**（评测工具依赖这些，不要改）：

- 工作流 ID 是 `ldsdt`，即文件夹 `.chrys/workflows/ldsdt/` 的名字；
- 文件开头的脚本元数据（`# /// script` 到 `# ///`）不要删，它让工作流使用仓库的 `.venv`；
- 模块最后必须有 `workflow = wf.build()`；
- 起点节点接收上面那段 JSON 输入。

**怎么开始**：模版里的 `ldsdt.py` 已经有两个 Python 节点（`prepare` 解析输入、`finish` 收尾），中间的 `TODO(Lab 0)` 注释写明了要做的几件事：

<Steps>

1. 在 `agents/` 下写一个智能体配置，例如 `agents/warmup.yaml`。格式和课程约束见 `agents/README.md`。写好后运行 `uv run ldsdt sync`，它在 iCode 中的名称是 `ldsdt-warmup`。
2. 在工作流中加一个智能体节点，使用这个智能体，并把它接进 `prepare` 和 `finish` 之间。
3. 决定由谁来写 `fr-list.json`：可以让智能体用写文件工具直接写，也可以让它只回复 JSON 文本，再由后面的 Python 节点解析并写入。两种都可以。
4. 用练习需求运行、检查、修改，直到产物正确。

</Steps>

几个容易踩的坑：

- 智能体节点只接收上一个节点的**文字**（`text`）。Python 节点在 `data` 里放的内容不会出现在智能体的提示里，也不会自动传到智能体节点之后。怎样把运行目录这样的信息带过智能体节点，见速查表的「在节点之间传递数据」。
- 改了 `agents/` 下的文件后，要运行 `uv run ldsdt sync` 才会生效。评测前会自动同步一次。
- 检查工作流能否加载：`uv run ldsdt doctor` 的最后一项，或者 `icode-zju workflow validate .chrys/workflows/ldsdt/ldsdt.py`。

**调试**：用练习需求运行一次，并按 Lab 0 的评分项检查：

```bash
uv run ldsdt try tasks/practice/todo-cli.md --lab 0
```

产物在 `runs/try/todo-cli/` 下（这个目录不会被提交），`result.json` 记录了检查结果，加 `-v` 可以在终端显示具体问题。想看智能体每一步做了什么，可以启动 `icode-zju`，按 **F1** 打开会话列表，找到这次运行的工作流会话，逐个节点查看输入与输出。

:::note[Windows 用户]
不要直接用 `icode-zju workflow run ... --input '{...}'` 手动运行：PowerShell 会改掉引号里的内容，工作流会收到不合法的 JSON。请用上面的 `uv run ldsdt try`，它会替你拼好输入。
:::

### 8. 评测、收集与提交

## 评分

| 评分项              | 分值 | 说明                                                              |

| 环境检查            | 30   | `ldsdt doctor` 全部通过                                           |
| 工作流运行完成      | 20   | 在两份练习需求上都正常结束（每份限时 10 分钟），取平均            |

## 常见问题

### 设置了环境变量，但检查时仍显示「未设置」

环境变量只在**新打开**的终端里生效。关掉所有终端窗口（包括编辑器里内嵌的终端）再开一个新的。macOS 上还要确认你改的是 `~/.zshrc`，并且保存了文件。

### 提示找不到 `icode-zju` 命令

运行 `uv tool update-shell`，然后重新打开终端。如果仍然找不到，运行 `uv tool list` 确认列表中有 `icode-zju`；没有就按[第 2 步](#2-安装-icode课程特供版)重新安装。注意命令是 `icode-zju`，不是 `icode`。

### `doctor` 中「Qwen 接口」未通过

- `HTTP 401`：Key 不对，检查 `LDSDT_QWEN_API_KEY` 是否完整、有没有多余的空格或引号；
- `HTTP 404`：地址不对，检查 `LDSDT_QWEN_BASE_URL` 是否与课程发放的完全一致；
- `HTTP 429`：被限流，稍等片刻再试；
- `无法连接`：检查网络。

改了环境变量后，要重新打开终端，再运行一次 `uv run ldsdt setup`。

### `ldsdt setup` 提示已有另一份名为 `ldsdt-qwen` 的模型配置

你之前手动建过同名配置。在 iCode 的模型配置窗口（F4）中删除它，或者运行 `uv run ldsdt setup --replace`，后者会把旧配置改名备份。

### 推送时提示输入密码或认证失败

GitHub 不再接受账号密码推送。macOS 上最简单的做法是安装 [GitHub CLI](https://cli.github.com/) 后运行 `gh auth login`，按提示用浏览器登录；也可以[配置 SSH 密钥](https://docs.github.com/zh/authentication/connecting-to-github-with-ssh)，并把 `origin` 改成 `git@github.com:<你的用户名>/<仓库名>.git`。Windows 上安装 Git 时自带的凭据管理器会弹出浏览器登录。

### `ldsdt try` 运行完成，但 `fr_list` 是 0 分

查看 `runs/try/<需求 id>/result.json` 里的问题说明，或加 `-v` 重新运行。常见原因：文件没写到 `<run_dir>/warmup/fr-list.json`（例如写到了仓库根目录），JSON 格式不合法，或者 FR 编号多了或少了。

### 智能体节点说找不到运行目录，或把文件写到了别处

智能体只能看到上一个节点的 `text`。请在交给它的文字里写清楚运行目录和输出文件的**绝对路径**。

### 下载很慢或失败

可以先给 uv 设置国内镜像再重试。macOS：`export UV_DEFAULT_INDEX="https://mirrors.zju.edu.cn/pypi/web/simple"`；Windows：`$env:UV_DEFAULT_INDEX = "https://mirrors.zju.edu.cn/pypi/web/simple"`。这个设置只在当前终端窗口有效。

其他问题请先查看[常见问题](../../course/faq/)页，仍未解决的在课程群中提问，并附上 `uv run ldsdt doctor` 的完整输出（输出中不含 Key）。
