本周实现设计模块。系统在大规模生成代码前，应当根据 Requirement IR 明确软件边界、模块职责、数据和交互契约，使前后端、实现与测试拥有共同依据。

## 需要实现

1. 将需求分配到模块或组件，明确职责与依赖；
2. 生成核心数据实体、约束与生命周期；
3. 用 OpenAPI、JSON Schema、类型定义或等价形式描述公共接口；
4. 记录影响实现的重要设计决策、备选方案与理由；
5. 建立 requirement → component → interface 的追踪关系；
6. 在进入实现前检查遗漏、循环依赖、未定义数据和契约冲突。

教学组不规定具体架构风格。设计模块既可以由专门 Agent 完成，也可以是同一 Agent 的受控阶段，但产物必须持久化并被实现与测试模块消费。

## 本周交付

- 设计模块接口与实现；
- 机器可读的架构、数据模型和接口契约；
- 需求到设计的追踪表；
- 自动一致性检查；
- 至少一项重要 Architecture Decision Record。

## 如何检查

教学组使用给定 Requirement IR 运行模块，检查：

- 每个必需行为是否被分配到明确组件和接口；
- 每个公共接口是否有输入、输出、错误和约束；
- 数据模型能否支持业务规则，接口引用是否一致；
- 修改一项跨模块需求后，设计能否识别受影响范围；
- 后续最小实现是否根据设计产物生成，而非完全绕过设计。

设计不按图表美观程度评分。重点是它能否约束实现、支持测试并降低跨模块误解。
