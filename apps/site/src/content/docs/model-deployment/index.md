模型部署是课程实验的第一阶段。你们需要把课程允许的国产大模型部署到指定国产算力平台，将它封装为可复现、可调用、可自动验收的模型服务。

阶段一只有一份操作文档：

- [Week 1：国产大模型部署](./week-1/)

## 学习目标

完成本阶段后，你应当能够：

1. 理解硬件、驱动、运行时、推理框架、模型权重和服务之间的依赖；
2. 根据兼容矩阵选择模型、精度和推理后端；
3. 用配置和脚本复现模型服务，而不是依赖一次性手工操作；
4. 将推理框架适配为统一 HTTP API；
5. 实现可重复准备、启动、状态检查、停止和重启；
6. 使用自动测试诊断生命周期、协议、流式响应和稳定性问题；
7. 获得可供工具设计阶段真实引用的 `deployment_id`。

## 阶段交付

每个小组需要交付：

1. 运行在指定国产算力平台上的国产大模型服务；
2. 包含部署清单、生命周期脚本、源码、配置、测试和文档的公开 Git 仓库；
3. 绑定不可变 Git commit 的正式评测记录；
4. 全部必选测试通过后签发的阶段一部署凭证。

模型服务必须支持健康检查、服务信息、非流式对话补全、SSE 流式补全、临时 Bearer Token 和统一错误结构。

## 自由度与边界

教学方固定：

- 国产算力平台和资源边界；
- 模型注册表与支持的推理后端范围；
- 部署清单、生命周期命令和服务 API；
- 端口、模型、临时凭据和日志的注入方式；
- 公开测试、正式评测和阶段凭证协议；
- 禁止使用外部模型 API 代替本地推理。

小组在兼容矩阵内选择模型、推理框架、精度或量化、上下文长度、批处理与并发参数，并自主设计内部代码、日志、缓存、错误处理和额外测试。

本阶段不要求修复底层驱动、从公网下载大型权重、源码编译复杂框架、训练或微调模型，也不进行跨组性能排名。

## 完成标准

阶段一必须同时满足：

- 提交结构和部署清单合法；
- `prepare` 可重复执行；
- 服务可统一启动、检查、停止和重新启动；
- 健康检查、服务信息、非流式和流式推理符合协议；
- 鉴权、非法请求和错误响应合理；
- 连续请求、少量并发和客户端中断后服务仍可用；
- 平台证据表明推理发生在分配的国产算力设备；
- 未观察到外部模型 API 转发；
- 服务可以注册为有效 `deployment_id`。

模型加载时间、首 token 延迟、生成速度和设备内存会被记录，但不用于跨组排名。

## 与工具设计阶段的关系
